# PB-35: Scans skip SHAPI's own contract tests

## Why

The first fix merged in production (shapi-demo#10, HubSpot Pipelines API v1) stayed open on the dashboard. After the merge, the rescan found 6 call sites instead of 5. The overview said "1 problem needs you", while the Problems badge and the score card both said 2.

The sixth call site was SHAPI's own contract test, `test/shapi/hubspot-pipelines-v1-sunset.test.ts`. The test names the retired path on purpose: its `retired()` helper checks `url.href.includes("/crm-pipelines/v1/pipelines/")`. The bare-URL pass read that string as a HubSpot call. Its method is unknown, so the advisory (`trigger: any`) matched it as affected.

So every merged SHAPI fix reopened its own problem. The next fix job could also have opened a PR against SHAPI's own test.

## What changes

- **`GENERATED_TEST_HEADER`** in `@shapi/core` is the first line of every contract test SHAPI writes (`// Generated by SHAPI for advisory `). `@shapi/repair` now builds the header from it.
- **`extractCallSites`** skips TypeScript and JavaScript files that start with that header, with or without a byte order mark.
  - They aren't listed as skipped, because nothing failed.
  - They don't count in `filesScanned`.
- **Matching is by header only.** A user's own test in `test/shapi/` with the same code is still scanned.

## Verified

- **New test, `packages/extractor/test/generated-tests.test.ts`:**
  - It covers the merged demo state, a byte order mark, and a user's own test without the header.
  - The first two fail before the change and pass after it.
- **Scanning shapi-demo at the merge commit:**
  - shapi-cli 0.3.1 reports 6 call sites and 2 affected, one of them `test/shapi/hubspot-pipelines-v1-sunset.test.ts:63`.
  - With this change it reports 5 call sites and 1 affected: QuickBooks, still open as shapi-demo#9.
- **Full suite:** typecheck and lint are clean, and the full test suite passes (53 files, 492 tests, 4 Linux-only skipped).

## Production

- After the deploy, the next scan of shapi-demo closes the HubSpot problem. A push triggers the scan, as does the dashboard's rescan.
- The CLI on npm (0.3.1) still reports SHAPI's own tests until the next publish (0.3.2).
