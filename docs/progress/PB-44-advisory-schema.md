# PB-44: The advisory JSON Schema is published at shapi.dev/schema/advisory.json (execution plan S-01)

## Why

The advisory format is SHAPI's open standard, but its JSON Schema only lived inside the repositories, with no stable URL. Editors, CI checks and other tools need one URL to point `$schema` at.

## What changes

- **The published copy.** `site/public/schema/advisory.json` is the schema as published. It's generated by `publishedAdvisoryJsonSchema()` in `@shapi/core`:
  - the same rules as `packages/core/schema/advisory.schema.json`;
  - `$id` set to `https://shapi.dev/schema/advisory.json` (`ADVISORY_SCHEMA_URL`), plus a title and a description.
- **Kept in sync.** The schema test fails when the published copy drifts. `UPDATE_SCHEMA=1` rewrites both files.
- **Served by shapi.dev.** VitePress copies the file into the docs build, and the docs server serves it as `application/json`. Files under `/schema/` carry `access-control-allow-origin: *`, so editors and online validators can load the schema from any origin.

## Verified

- **Tests:**
  - every advisory in `advisories/` (64 files) validates against the published schema with Ajv: draft 2020-12, strict mode, formats checked;
  - Ajv rejects an empty trigger, an unknown severity and a non-date `effectiveDate`;
  - the published copy matches the generator and carries the `$id`;
  - the docs server serves `/schema/advisory.json` as JSON to any origin, and other files without that header.
- **Docs build:** `pnpm --filter @shapi/site docs:build` puts the file at `dist/schema/advisory.json`.
- **Full suite:** typecheck, lint and the full test suite.

## Not changed

- **Advisories site page.** `site/advisories.md` still links to the schema on GitHub. That file has uncommitted edits in the shared checkout, so the link goes to the canonical URL in a later change.
- **Mirror.** The shapi-advisories repository's schema rules are unchanged, so it needs no new mirror PR.
