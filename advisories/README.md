# SHAPI advisories

**The source of truth is the public repository [SriVarshini09/shapi-advisories](https://github.com/SriVarshini09/shapi-advisories) (CC BY 4.0).** Add or change advisories there; `pnpm advisories:pull` refreshes this folder, which is bundled into `shapi-cli` and used by the tests. The hosted worker syncs the public repository directly (`SHAPI_ADVISORIES_REPO`).

One JSON file per breaking change, named `<id>.json` and validated by `AdvisorySchema` in `packages/core/src/advisory.ts`. The format is open. Each advisory has: provider, endpoint pattern (`{param}` matches one segment, `*` matches within a segment, `**` matches any number of segments, `{?}` matches only a value the code builds at runtime, such as a model an SDK passes as a parameter, never a literal), change class, trigger (what in a call site's dependency surface makes it affected; for a GraphQL endpoint, `graphql` names the root fields, paths or field names whose selection makes a call affected, optionally only in a `query` or `mutation`), first observed, published notice, effective date, severity, migration note, optional recipe id, sources, and status.

`status: "verified"` means the facts were checked against the provider's own notice or two independent sources. `"unverified"` means secondary reports only. Every verified advisory carries `provenance`: for each source that backs it, the provider's words exactly as the page says them (`quote`), the SHA-256 of the page as it was fetched (`sourceSha256`) and when (`fetchedAt`). CI checks every quote against the snapshot in `evidence/snapshots/` (see [evidence/README.md](evidence/README.md)). `drafts/` (Milestone 2) will hold machine-generated advisories awaiting review; it is not loaded.
