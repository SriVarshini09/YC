How SHAPI works

One API change, start to finish.

01 · MAP

Read what your code expects.

Every call site goes into api.lock: the endpoint, and the status codes, fields, headers and query params your code relies on.

02 · WATCH

Probe the providers every hour.

Canaries call each API and record the shape of the answer. When a shape changes in a breaking way, an advisory is drafted for review.

03 · MATCH

Only the code that breaks.

The advisory is matched against api.lock. A call that checks for 204 is flagged; a call that only uses the endpoint is left alone.

04 · FIX

A fix that has to prove itself.

SHAPI writes a contract test, confirms it fails, applies the recipe, and keeps the change only once the test passes.

05 · SHIP

A pull request with its evidence.

The change, the test, and why: the advisory, its sources, and the test runs before and after.
